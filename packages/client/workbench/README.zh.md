# @deepseek-ai/dsh-client-workbench

[English](README.md) | 中文

工作台的浏览器半边：对话旁边的「工作台」tab。三栏 —— 说明你在哪的目录、说明这个模块是什么的一张卡、装着这个模块上说过什么并且输入框贴在下面的一栏。树、闸门和所有写入由 [dsh-workbench](../../workbench/workbench/README.md) 拥有；设计记录见[卡片模型 Agent Note](../../../.agents/notes/implemented/feature/2026-08-14-workbench-card-model.md)。

左栏是**一条扁平缩进列表**，不是分组带：一行带一个记号、一个标题，以及仅在非零时才出现的一个计数。分组带**互不排斥**，所以同一张卡会同时出现在两三条带里 —— 行首的 `⚖` 能说明「这张卡管着别人」，不必再给它第二个落脚处。**没有计量条**；它原来承载的那几个记账数字目前**没有落点**（见「已知限制」）。

输入框是**平台那一个**，不是第二个输入框。本视图声明 ui-conversation 的 `conversation.view.composer` 座位，于是已有的那棵 composer 子树渲染进右栏底部，草稿、图片、chain election 全都保住（[决定](../../../.agents/notes/implemented/feature/2026-08-17-conversation-view-composer-dock.md)）。因为它在栏内，本视图**不留底部避让**。

折叠以及它渲染的每一个派生量，都来自那个包的 `./projection` entry —— 与宿主跑的是同一份代码。这里不重算任何依赖集、子模块图或成熟度标记。

## 一张卡、四段、两态

一张卡有标题行、选内容的 tag 条、一个内容体、一排辅助按钮。每一段都有上限（三条元数据、两个动作、一个抽屉），超出上限的一律进 `⋯`，于是「保持能一眼看完」站得住，同时没有东西变得不可达。

## 裁决一棵骨架

提**整批新卡**（而不是改某张已有卡）的草稿有自己的界面，位置在卡片**上方**，与当前选中了什么无关。它按 `parentIndex` 缩进列出提议的每张卡，每张都能改标题、能剪掉。采纳时把保留下来的下标连同人定下的标题一起送出，宿主**在提交之前**剪枝，所以被剪掉的卡**从来没进过树**。剪一张会连它下面的一起剪，因为宿主会拒绝把孤儿改挂到根上的采纳，而界面不该提供一个注定被拒的状态。「不要」会就地问那条拒绝必须带上的理由。

**选中不是它的开关**：骨架是一个等着人裁决的决定，而把它藏在「没有选中卡片时才显示」后面，正是模型的第一份产出变得够不着的原因——采纳原来只渲染在被选中的卡片内部、且只过滤指向那张卡的草稿，而冷启动的草稿谁也不指，树上又没有卡可选。

指向某张已有卡片的模型草稿不是第二种卡：它把这张卡推进**编辑态**，而「改这张卡」推进的是同一个状态。编辑态带虚线边和一条「确定／丢弃」横栏，并且落在宿主的日志里，所以它活过刷新、也活过换机器。

tag 条区分两类内容。**撰写体**（简介、表格、流程、论证）有自己落盘的真相，可以删，并在比同卡上更新的体更旧时被标 `⚠`。**派生视图**（带 `⁄` 前缀：子模块图、关系图、全局约束、想法、图表）每次现算，所以既不能编辑也不会过时。tag 自己带着要展开的体或视图，而不是一个指向另一张表的键，因此 tag 条与内容体区不可能给出不一致的答案。

`⁄想法` 这一格**每张卡都有**，而卡片仍然打开在**自己的内容**上：默认视图是第一个撰写体，所以一张什么都还没有的卡会说「还没有内容体」，而不是打开在一个空的想法区上。想法区有**自己的**空态文案——它是唯一在「没人动过的卡」上就已经是空的派生视图，所以它说的是「这里是干什么的」，而不是「没有可画的东西」。

双击内容体里一个可寻址的对象 —— 表格的一行、流程的一步、论证的一条论据 —— 会把对话锚定到它；双击子模块图里的一张卡则下潜进去，面包屑负责回来。

每个问题都在原地一行里问。弹窗会把光标从人正在打的字上抢走，而这恰恰是「结果到达」这条路唯一不许做的事。

## Known Limitations and Deferred Work

- **`⚠` 只答「哪个更旧」，不答「它们是否矛盾」** —— 真检查是宿主还没有的一次模型扫描。
- **锚点在它所在的内容体被替换后失效** —— 替换一个体的提案会把对象 id 一起带走。
- **对话摘要按模块，历史不按** —— 摘要按「这句话是在哪个模块上说的」过滤，会话本身仍是一条线。
- **选中、打开的 tag、论证选的形态都是浏览器本地的** —— 都活不过刷新，因为它们都不是内容，宿主也没有对应的事件。
- **记账数字没有落点** —— 承载它们的计量条（AI 写的未改节点数、正文均长、字段词汇）被删掉了，因为在空项目上每个数字都是 `0`。**它背后的需要仍然成立**：人对自己「验了多少」的感觉不可靠，所以这个数必须来自外部。落在哪未定，候选是按卡片记、为空时不显示。
- **打字在离开输入框之前都是本地的** —— 输入框绑本地草稿、失焦才自动保存，【确定】会把这份草稿一起带上。直接把输入框绑到宿主存的草稿会和往返赛跑，把打进去的字丢掉大半。代价是两次失焦之间崩溃，会丢掉上一次失焦之后的按键。
