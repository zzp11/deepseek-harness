# @deepseek-ai/dsh-workbench

[English](README.md) | 中文

工作台的宿主半边：一棵节点树，唯一的持久化载体是会话日志。节点存的是"关于世界的陈述"；一手层（原话，之后还有材料）只追加。两条写路径——人编辑、模型提议——汇聚到同一次 append，每次落盘把单调的全局 `rev` 加一。

这套设计要守住的两条约束：人的编辑即时落盘，不触发模型调用、不等待；模型只能 `propose`，它产出的东西没有人的裁决就进不了本体。

浏览器半边是 [dsh-client-workbench](../../client/workbench/README.md)；设计记录是[工作台 Agent Note](../../../.agents/notes/implemented/feature/2026-08-14-workbench-idea-to-commitment.md)。

派生量只在 `core.ts` 算一次。它把读模型当参数收进来，不碰 I/O、不碰 cordis、不碰会话日志，所以不启动 harness 也能测——也所以没有哪个消费方会有机会把依赖集算出第二种样子。`store.ts` 故意不另外提供 `children` 或 `dependencySet`：它的投影本身就满足 `core.ts` 的读模型，调用方直接用那一套。`edit.ts` 同样是纯的：进去一个请求和一份投影，出来要 append 的事件，于是"人被允许做什么"不启动 harness 就能证明，而 `index.ts` 只是把它 append 出去的胶水。

## 写路径是命令，不是网关方法

人的编辑以 `workbench-edit` 到达——一个由界面**程序化**派发的注册命令，没人手打斜杠。`commands.execute` 本来就是 Remote，命令名是运行时查注册表，所以这条写路径不需要新 wire 方法、不需要生成描述符、不用碰 API 网关一行。

handler 回的是 `{ kind: 'success', sourceEventSeq }`，不重述变更：客户端从它本来就订阅的事件流里读那条真实的 `workbench/node-change`，新的 `rev` 和作废清单也在那儿。被拒的编辑回 `{ kind: 'error', text }`，点名是哪条闸门拒的。

## 闸门作用在哪

工作区（念头／想法）**故意**不设闸——那里的摩擦是在给思考收税。已承诺区设闸，于是"严谨"的全部代价落在一个时刻：晋升。未登记的字段、没依据的取值、有子节点却从没说清自己管什么的模块，都是在那一刻才不再被容忍。结构性闸门（引用都能解析、树还是树）全区生效，因为坏掉的树不是草稿。

采纳草稿时，闸门重跑的是**人改完的**内容，不是模型提的内容。刀在人手上；但人手改完的草稿，落盘之前照样得是一棵合法的树。

## 一手层镜像

自定义会话事件永远进不了模型请求，所以人的话要走两趟：一趟是模型读的 `user/message`，一趟是树引用的 `workbench/utterance`。镜像是一手层条目的**唯一**生产者——正因为唯一，"每条消息恰有一条条目"才能是不变量而不是期望。本包的 `./invariant` 在每条条目落地时校验它，所以漏掉一条会在下一条落地时暴露。

## 内容体：撰写体，或派生视图

一张卡的内容是一串内容体。**撰写体**有自己的真相、存在节点上、会过时：`brief`、`table`、`flow`、`argument`。**派生视图**每次由树现算、从不落盘：子模块图、关系图、全局约束列表、想法区、图表。

这条切分由类型系统执行，不靠测试：`BodyPayload` 里没有任何 `DerivedViewKind` 的变体，所以派生视图无法被表示成可存储的内容。`derivedViews()` 返回算好的视图而不是 kind，于是调用方永远不必处理「被告知它存在、却做不出来」。

图表是派生的、不是撰写的，判据从严：一列只有在每一格都匹配 `/^-?\d+(?:\.\d+)?$/` 时才够格。让模型写图表会让数字失去可核验的来源，而错一格画出的柱子看起来完全正常。没有够格的列时，这个视图**不出现**，而不是出现一个空的。

`brief` 必有且不可删，因为 `duty` 是全局骨架里代替模块正文的东西。卡片创建时就带一个；`duty` 与 `body` 住在节点上（闸门、依赖集、系统提示都在那里读），`syncBrief` 在提交点把它们抄进 `brief`，只为读日志的人和读 `bodies` 的模型 —— 从不当作真相读回。模型提的 `brief` 无论有没有说，都替换既有那一个。

## 冷启动的骨架是一棵树

草稿的 `newNodes` 可以描述**一整棵树**，而不只是一个扁平列表：条目的 `parentIndex` 按位置指出它的父节点在同一个列表里的哪一项。冷启动时 `parent` 做不到这件事——它是一个**已存在**的节点 id，而冷启动时什么都还不存在，于是每张卡都会落到根上，模型已经想清楚的结构被白扔掉。

`parentIndex` 必须指向**更靠前**的条目。这样按构造就排除了成环，而按从上到下写这棵树自然就满足，不用刻意为之。`planProposal` 会拒绝违反这条规则的草稿：这个字段只有模型会写，而一份形状根本搭不起来的草稿，值得在模型还能改的时候就拒掉；它同时把草稿自己的占位节点也放进图里再跑闸门，于是 index 形式的父节点不会被当成悬空引用，完全落在一份草稿内部的环也能被环检测看见。

采纳时**先为整个保留集铸 id，再解析父节点**，所以一张卡可以挂在同一次提交里新建的兄弟节点下。剪掉一张**仍有子节点被保留**的卡会被**拒绝**，不会悄悄把它们改挂到根上：「门票」挂在「预算」下是一条预算科目，挂到根上就成了一件自成一体的事，而这条拒绝把选择权留给人。

## 编辑态，以及想法所在的区域

`workbench/scratch` 承载一张卡未提交的编辑态，所以它活过刷新、也活过换机器。它从不推动 `rev`，并且**不放在 `WorkbenchNode` 里** —— 是 `NodeGraph.tmp` 单独一张表 —— 于是注入路径拿到的类型里没有这个字段，把未提交的草稿泄漏进模型请求是**写不出来**的。`at` 由本进程的时钟盖章；wire 类型不带它，所以浏览器写不进日志里一个时间。空 draft 会在一张已提交的卡上打开编辑态，这正是人手动开始修改的方式。

**每张卡都有想法区**，不管有没有开过：`derivedViews` 总会带上 `ideas` 这个视图，在想法根出现之前它是空的。放一个「还不算承诺」的想头的地方，必须在那个想头出现**之前**就在，否则人已经把它放到别处去了；空态说明「这里是干什么的」，做的正是原先靠隐藏 tag 想做的事。

带 `region: 'idea'` 的节点是一个想法区的根。可见性只有一条规则：**包住它的每个想法根都得包住发起点** —— 所以父看不见、兄弟看不见，这张卡自己的子模块也看不见。`renderSkeletonIndex` 按视角过滤，那是想法唯一可能进入模型请求的地方。

## Model Experience

### Tool schema

#### What the model sees

`workbench_read_nodes`、`workbench_propose`、`workbench_check_promotion` 的生成 schema —— 见[生成编目](../../../docs/tool-catalog.md#deepseek-aidsh-workbench)。`workbench_read_nodes` 的 `nodeId` 是**可选**的：不传就只返回约束区和树的索引，冷启动就是这样拿到第一个 id 的，空树也是这样报告自己是空的。`workbench_propose` 收草稿——标题、可选的目标节点、正文、字段，以及要新建的节点，其中 `newNodes[].parentIndex` 让一份草稿能描述一整棵树——按位置指出每一项的父节点在同一列表里的哪一条。`workbench_check_promotion` 收一个节点 id。

#### Token effect

工具可见的每次请求上都是固定的 schema 开销。

#### KV Cache effect

定义与可见性不变时前缀稳定。

### System prompt section

#### What the model sees

本插件注册作用域内的每次请求都带着下面这个章节。它的第一条指令是冷启动那次读，其余讲成熟度档位和模型不能做的两件事。

##### 能做什么、不能做什么

```markdown
- **先不带 `nodeId` 调一次 `workbench_read_nodes`**，看树里现在有什么。树可能是空的——那就直接提骨架。
- 要在某个节点上作业，再带上它的 id 调一次，拿它的**依赖集**。那是机械展开的、完整的、未经取舍的。**不要自己推断还需要什么**：需要别的节点，就再调一次。
- 你唯一的写路径是 `workbench_propose`。它产出**草稿**，不进本体。人会看、可能改、然后采纳或不要。
- 你**不能**晋升节点。晋升是人的动作。`workbench_check_promotion` 只告诉你某个节点现在过不过晋升门、缺什么，好让你用 `workbench_propose` 去补。
```

##### 闸门作用在哪

```markdown
**只有已承诺区设闸门。**在念头和想法上工作时不要自我审查——那里的摩擦是在给思考收税。已承诺区里，每个开放字段都必须已登记、且指向一手层里它是从哪句话来的。
```

##### 最该避开的那一种失效

```markdown
把新概念写进 `正文` 而不加字段，是这套东西最容易静默失效的方式：闸门恒绿，报告全过，而结构化实际上已经停了。发现自己在正文里反复讲同一类事实时，把它提成一个字段，并指出依据。
```

#### Token effect

固定，且相对一份依赖集来说很小。

#### KV Cache effect

静态文本、order 固定，所以留在缓存前缀里。

### Tool-call history and results

#### What the model sees

`workbench_read_nodes` 的返回渲染成展开文本：先一段头注说明这份集合是完整的、未经取舍的，然后每个条目在自己的标题下（`【自己】`、`【父链】`、`【全局约束】`、`【依据】`、`【骨架】`），带 id 和 `rev`。`workbench_propose` 回 `草稿 <id> 已记下，等人裁决。`，或者拒绝它的闸门发现，每条一行 `<CODE>: <message>`。`workbench_check_promotion` 回 `<id> 现在过晋升门；晋升要人来点。`，或者同样的发现行。

#### Token effect

一次读的返回就是它展开的那些东西的大小：节点本身、祖先的职责与正文、约束区、被引用的原话，以及索引里每个节点一行。全程不做摘要，所以随树增长的项是索引的行数。

#### KV Cache effect

只追加；返回落在可复用的请求前缀之后。

## Known Limitations and Deferred Work

- **`⚠` 过时只答「哪个更旧」，不答「它们是否矛盾」** —— `staleBodies` 比的是 `lastRev`，真检查是本阶段没有的一次模型扫描。过度报告看得见，缺检查是静默的。
- **`workbench/scratch` 无法标成 `ignorable`** —— envelope 定义了这个标记，但 `Session.append` 没有设置它的入口，所以这个 required-on-read 的成员会被不认识它的构建拒绝。它本来够格，而让这一点继续成立的约束是：提交带的是整个已提交节点，不是一个指向编辑态的引用。
- **检查点随一手层增长** —— `workbench/snapshot` 带的是整个投影，含一手层条目。因为不带它们的检查点会让冷启动跳过前缀，而被跳过的正是树上字段所引用的条目。这就是"整值检查点被投影后端替换之前，会话长度的真实上限"的来处。
- **失效只做 1 跳，且没人消费** —— `invalidate` 给的是直接子节点，或者约束变更时给约束区之外的全部节点。骨架索引**故意**不算作边，所以改名不作废任何人。
- **只有标题的节点没有形态候选** —— 而刚被 propose 出来的节点正是这个状态，所以浏览器必须自己渲染空态。
- **作者归属只到节点，不到字段** —— 模型里没有地方记"人重写了某个 AI 写的字段"，所以"树上还剩多少一字未改的模型散文"只能按节点粒度数。`structuralHealth` 量的是相关的那个趋势（正文在长而字段词汇量不长），作用在一个检查点的节点集上；目前还没有谁报告它。
- **镜像的最后一条无法在运行时断言** —— 因为 `session.append` 拒绝重入，条目是在后一个微任务里追加的，所以最新那条消息的条目"暂时缺失"是合法的。不变量抓得住之前的每一个缺口；只有"漏在最后一条"这一种需要靠测试而不是靠检查。
- **想法的不可见性只在依赖集上被强制，不在 transcript 上** —— `renderSkeletonIndex` 按视角过滤，所以想法**经由工具**永远进不了模型请求。但在想法区里**说过的话**是普通 `user/message`，留在 `session.deriveMessages()` 里，之后每一次请求都整条带着它。补这个洞**不是插件改动**：有一条不变量要求请求消息与持久化折叠**完全相等**，不等就报 `log-reconstruction desync`，所以按模块切分要么每模块一个真子会话，要么把作用域做成落盘的投影。
- **提示性发现没人消费** —— plan 会报出不阻塞的发现，但没有界面显示它们。
- **阶段 0 自觉地没有巡检流** —— 一致性只在写路径上检查（闸门），落盘之后没有任何异步检查。所以阶段 0 交付的是设计的前段加晋升门，不是完整闭环。
- **导出尚无归属** —— 本体只活在会话日志里，所以"从树机械投影出成果"（层级变标题、正文原样搬、没定的照实标成没定）是必需项而非加分项，目前未排期。
