# 一、定位与核心价值

## 1.1 定位

> **一个把人的念头逐级实体化的单页工作台**：念头 → 想法 → 已承诺 → 可验证／可执行。
> 每一级的摩擦与机器约束强度不同；AI 在每一级都以助手身份异步跟随，人始终主刀。

**它不是什么**：不是聊天工具（对话按模块切分，不是一条线性历史）；不是文档编辑器（AI 是一等参与者，
且有机器闸门）；不是 AI coding 工具（领域模型已抽掉，骨架字段与任何主题无关）。

**前段像思维导图**（低摩擦、允许乱、允许矛盾并存），**后段像项目工作台**（持久、结构、联动）。
这两段不是两个需求，是同一条路的两截 —— 判据见 §2.1。

## 1.2 核心价值

> **提升人单位时间内产生、理清并落实有效想法的数量与质量。**

**为什么不写成"提升人的认知能力／创造能力"**（U13 的原话是"提示人的认知能力/创造能力"，
△ 我按"提升"读）：〔事实〕人的工作记忆约 4 个组块（Cowan 2001），这是生理常数，工具改不动。
可着力改造的不是带宽本身，是**同一份带宽能承载多少意图**。

这不是抠字眼：**"提升能力"给不出检验方式，"提升产出率"给得出**。前者是愿望，后者是判据（M4）。

配给带宽仍然是这个工具做的事，但它是**手段**，不是目的（这一条是本方案在 U13 之后的定位修正：
此前一版把配给写成了目的）。三个动作：

| 动作 | 落法 |
|---|---|
| **切分** | 内容切成节点树，每个单元能折叠成一行；上下文按模块切分 |
| **节流** | AI 的产出不自动入本体；巡检建议有容量上限；工作集上限 4 |
| **送达** | 依赖集在人发起的那一刻，把跨时间跨模块的相关事实精确送到 |

## 1.3 适用分档与失效边界（M13、M7）

| 场景 | 结论 | 依据 |
|---|---|---|
| 一次性问答 | **明显亏** | 结构化成本全是白付 |
| 单次长对话、一次性产出 | **亏** | 一份 md 更快。〔事实〕方案B 08-07 实际发生的就是这个 |
| 跨天、同一份内容反复改 >10 轮 | **可能正** | ○ 无数据 |
| 产出要被下游机器消费 | **正** | 〔事实〕喂精确上下文 3 轮/$0.46 vs 让 AI 自己搜 6 轮/$0.91 |

**失效边界**：本方案的全部收益都以"内容会被反复回来改"为前提。若使用形态是一次性的，
§五的依赖集、调度器、跨天接续全部是白做的。

## 1.4 判据

| 维度 | 判据 | 状态 |
|---|---|---|
| **产出率** | 单位时间内新增的「已承诺」节点数（晋升门的通过量） | 可测，且**晋升机械可判定** |
| **准确性** | 已承诺的内容里事后被推翻的比例 | 可测 |
| **创造性** | ○ **无判据** | 见下 |

**○ 创造性这一条不填。** 候选判据是"人自认『不用这个工具想不到』的想法条数"——主观，
且〔事实〕C6 表明人对自己的判断不可靠（客观慢 19% 而主观觉得快 20%）。
**宁可留空位，不许沉默填补**（禁 10）。对照组能给一个弱证据：同一主题做两遍，
比较想法条数与顶层结构的差异度。

**判据必须带对照组。**〔事实〕方案B 的实测里唯一可信的一条是"喂上下文 vs 让 AI 搜"，
因为只有它有对照组；其余全是单臂，单臂测出来的数只能自证。

# 二、主要矛盾与它们的共存机制

四对矛盾，每一对都给出共存条件而非折衷（M11）。**它们不是并列的：2.1 规定这个工具是什么，
其余三对规定它怎么工作。**

## 2.1 主要矛盾：发散 ↔ 收敛

**创意需要低摩擦、允许混乱、允许矛盾并存；落实需要结构、判据、一致性。**
同一份内容在同一时刻，不可能既允许矛盾并存又不许自相矛盾。

**这对矛盾一度被我忽略**：在 U13 之前的设计里，闸门体系（未登记字段拦下、提炼须标依据、
增量递进）是无条件生效的。它们在"掌控"这个目的下是核心，在"迸发创意"这个目的下是敌人 ——
念头刚出来就要登记字段、灵感来时没有依据可标。

**共存条件：节点带成熟度，闸门按成熟度作用；全部摩擦集中到一个动作上。**

| 区 | 闸门 | 字段 | 矛盾 | AI 产出 | △账 |
|---|---|---|---|---|---|
| **未承诺**（念头／想法） | 只有结构性（`parent` 悬空、成环）＋ 否决无理由 | **随便加，不登记** | **允许并存** | 可原样吞下 | **不计** |
| **晋升门** | ← **全部摩擦集中在这一个动作上** | | | | |
| **已承诺** | 全开 | 须登记 | 不许 | 须裁决 | 计 |

△ 「否决无理由」为什么在未承诺区也生效、而这不构成摩擦：
**`已否决` 只对认真考虑过的东西有意义。一条念头不想要就直接删**（人的编辑流免费），
不必走"否决"。所以念头区实际上永远碰不到这条闸门。
若真要否决一条念头，说明它被认真考虑过了，此时填理由是值得的 ——
〔事实〕方案B 的依据：否决理由是防止同一件事被反复重提的唯一手段。

〔推论〕低摩擦与高一致**不在同一个位置上竞争**。晋升是低频的、人主动的、有明确收益的
（"我决定要做这个了"）——**人愿意在那一刻付摩擦，不愿意在每一个念头上付。**

△ 这条判据不是新编的：〔事实〕方案B 用"是否已被采纳并承诺实现"划分想法面与产品面，
判据是**有无晋升记录**，已验证可机械判定。本方案抽掉了四面，但这条判据与领域无关，
故留下并**从"面的划分"降级为节点上的一个字段**，更轻。

## 2.2 独立性 ↔ 关联性

会话独立才便宜、才不用等；但独立会让内容自相矛盾。

〔事实〕方案B 的成本单调递增（连续三轮 $0.31 → $0.54 → $0.74，按斜率 8–10 轮到 $1.5+/轮），
机制是单一线性上下文——谈第三个模块时前两个模块的全部对话都还在输入里。

但按模块切分之后会出现这个失效：「场地」定了"不能卖票"，三天后「预算」按门票算收入，
**两个会话各自都对，全程无信号**。

**共存条件：依赖集（§五）。** 会话独立，但每次发起时按依赖集把相关事实精确注入。

## 2.3 通用性 ↔ 机器可判定性

内容越不限定领域，机器能替人判的越少。方案B 的闸门全部挂在四面结构上，抽掉领域模型
就抽掉了判据来源。

**共存条件：骨架层固定（闸门只写在这一层）＋ 字段层开放（通用性由它承担）＋ 字段须登记
（生长有人签字，故前后可比对）。** 见 §3.1、§3.2。

## 2.4 即时落盘 ↔ 一致性检查

人的编辑要即时生效、零成本；但落盘后全局可能不一致。
若每次手改都跑全树闸门，人会卡，"即时"就没了。

**共存条件：落盘即时，影响异步。**

〔推论〕**这条推出一个重要结论：巡检不是"锦上添花的助手"，是架构必需。**
落盘的即时性与一致性检查的完备性不可能在同一个动作里同时满足；巡检就是这对矛盾的
共存机制。抽掉它只剩两条坏路：每次编辑都卡（一致但不可用），或永不检查（可用但内容会烂）。

# 三、内容模型

## 3.1 骨架九字段

| 字段 | 语义 | 为什么它与领域无关 |
|---|---|---|
| `id` | 标识 | — |
| `标题` | 一行内说清这个单元是什么 | 折叠成一行的那一行 |
| `parent` | 层次归属 | **层次化**落在这里 |
| `职责` | 管什么、不管什么，一两句 | **模块化**落在这里，且可判定；并且它是**全局骨架里代替正文的东西**（§5.1） |
| `成熟度` | 念头／想法／已承诺／已否决 | **§2.1 的载体**，闸门按它作用 |
| `来源` | ◆人 ／ △AI ／ 指向一手层条目 | 归纳必须能回到一手材料 |
| `正文` | 散文态内容 | 人读的主体 |
| `验证判据` | ○无／愿望／可执行 | **v2 预留**，见 §十 |
| `执行动作` | ○无／愿望／可执行 | **v2 预留**，见 §十 |

记账字段一个：`last_rev`（该节点最后一次落盘时的全局 `rev`）。

**两处合并，均为消除术语混用：**

- **原设计有 `状态`（待议／已定／已否决）与 `成熟度` 两个字段，已合并为 `成熟度` 一个。**
  理由：`已定` 与 `已承诺` 指同一件事，混用过就得进词典（§9.3），不如现在不混。
  `已否决` 是终结态，与承诺程度正交，故并入取值域并保留"否决须填理由"闸门。
- **原设计有 `最近触及轮次`，已由 `last_rev` 取代。** 一个单调计数器承担两件事：
  失效判定与"多久没被碰过"。

**`成熟度` 的取值域完整定死，v1 只实现前三档的闸门差异**：新增档位会迫使已存节点重判成熟度，
那是数据迁移。

## 3.2 开放字段与登记

其余一切都是开放字段（`立场`／`论据`／`规则`／`例子`／`明细`／指向别的 id ……），
由 AI 提出、人裁决、进 `字段词典.yaml`。

**未登记字段闸门：AI 现编一个没登记过的字段 ⇒ 拦下。** 处置分两类，不许合并：

| 情形 | 归谁 | 页面上 |
|---|---|---|
| 词典里已有语义相同的字段 | **机械类，归 AI 自修** | 人看不到这一轮 |
| 确实是新概念 | **语义类，归人裁决** | 弹字段登记卡（字段名／AI 给的语义／值的形状／算出的可用形态） |

**闸门只在已承诺区生效**（§2.1）。念头区随便加字段，晋升时一次性补登记。

**什么进骨架、什么进开放字段，判据是：**

> **工具要据它做分派的字段进骨架；工具只负责渲染的进开放字段。**

`验证判据`／`执行动作` 驱动 v2 的执行分派 ⇒ 骨架。代价：骨架越大越僵，
换来的是工具能认识它们。

**○ 字段无作用域**（不限制"只有某类节点能带某字段"）。△ 理由：限制作用域需要"节点类型"
这个概念，而骨架**故意没有类**——加了类等于把领域模型偷回来。代价照实记：
字段词典会长成大杂烩，○ 多少个字段之后读不动，无数据，不拍。

## 3.3 一手层：三类，开放枚举

共同硬属性：**不可改、只追加、可被 `依据` 引用**。

| 类 | 来源 | v1 |
|---|---|---|
| `原话` | 人在工具里说的话 | 有 |
| `材料` | 外部导入（含自动检索） | 有 |
| `执行记录` | 机器跑出来的痕迹 | **v2，位置现在留**（§十） |

**类型是开放枚举而非二选一**，否则 v2 加第三类要迁移。

**`依据` 字段的去向定义为"一手层任一条目"**，不是"原话或材料"。当时的理由是
"悬空引门只写一遍"，v2 才显出第二个理由。

**提炼无依据闸门**（**仅已承诺区**生效，见 §2.1）：每条提炼类字段必须带 `依据` 指向一手层条目，
标不出的拦下。**举证责任归 AI**，不做语义匹配（做不了，也不可复现）。

○ 这条只能验到"标了没标"，验不到"标得对不对"。AI 可以标一个不相关的 id 来糊弄。
〔待检验〕抽查 20 条提炼，人工核对 `依据` 指的那句话是否真支持这条提炼，记错误率。

## 3.4 全局约束区

**判据：一条内容若约束的是别的模块，它就该提升为全局约束。**
"礼堂要提前两个月申请"只约束场地自己 ⇒ 不提升；"不能卖票"约束预算与报名 ⇒ 提升。

由 AI 提议、人一键确认。**巡检把这件事当一类固定任务**（§9.1）。

△ **全局约束区是 `内容.yaml` 里的一棵特殊子树（`G-` 前缀），不另立文件。**
理由：它是内容、会被人编辑、走同一条落盘路径与同一个 `rev`；另立文件就要两个 `rev`、两套落盘。

○ 代价：提升一条约束会让**所有**在跑任务作废、所有会话换新（因为全局约束区是每个依赖集的
固定项）。提升是低频动作，v1 接受；若实测发现频繁，再按相关性分条注入。

## 3.5 形态由字段派生，分派在节点粒度上

| 该节点实际带的字段 | 算出的可用形态 |
|---|---|
| 只有 标题＋正文 | 段落卡 |
| 有子节点 | 嵌套框／可折叠树 |
| 有指向别的 id 的字段 | 关系图 |
| 有同构对象列表 | 表 |
| 有 `立场`／`论据` | 论证图 |
| 有有序步骤 | 流程 |

**人只在算出的候选集里切换，不能任选**；否则形态变成人声明的，会与内容漂移。
**切换不改内容。**

〔推论〕结构化程度按需付费：一条刚出口的念头只有 标题＋来源＋正文，就只有段落卡；
争起来了才长出 `立场`／`论据`，才有论证图。不需要额外机制。

○ "同构"的判据未定：3 个元素里 2 个有 `金额`、1 个没有，算不算同构。**判错是静默的**
（算成表，第 3 行空一格，人以为数据缺了）。判据须写死在 `core.py` 并配 5 组边界列表的否证测试。

## 3.6 文件清单

| 文件 | 性质 |
|---|---|
| `内容.yaml` | 节点树 ＋ `meta.rev`；含 `G-` 全局约束子树。**唯一本体** |
| `原话.jsonl` | 只追加 |
| `材料/` ＋ `材料索引.yaml` | 原件不动，切片可寻址 |
| `字段词典.yaml` | 经裁决增改 |
| `裁决.jsonl` | 只追加；**兼作跨时间上下文载体**（§5.5） |

**版本用全局单调 `rev`，不用 hash**：hash 只能判"变没变"，`rev` 能判"谁更新"，
且失效判定退化成一次整数比较。每次落盘 `rev += 1`，节点记 `last_rev`。

**原则：本体存"关于世界的陈述"，一手层存"世界的痕迹"。**
`内容.yaml` 里永远不出现代码文件内容、API 响应体、diff —— 那些是一手层的东西，本体只引用。
零实现成本，但它约束每一个设计决定；没有它，v2 会发现本体已被外部内容污染。

# 四、三条流（＋v2 的第四条）

分流判据：**谁发起 ／ 改不改内容 ／ 累不累积上下文**。每条各自可测、可关、可单独否证。

| 流 | 谁发起 | 上下文累积 | 改内容 | 成本 | 可作废 |
|---|---|---|---|---|---|
| **① 人的编辑流** | 人 | — | **直接改，就地生效** | **0** | — |
| **② 模块会话流** | 人（在某模块内） | 是，**按模块隔离** | 经草稿-预演-裁决 | 每模块独立递增 | 可 |
| **③ AI 巡检流** | AI（事件触发） | **否，无状态短会话** | **不改，只产建议** | 需预算与开关 | 可 |
| **④ 执行流（v2）** | 人委派 | — | 经裁决 | 长时 | **不可**（有副作用） |

## 4.1 人的编辑流：写盘权按发起者分，不按内容分

**这是本方案对方案B 最大的一处修正，且它是性质修正不是程度修正。**

〔事实〕方案B 的写权边界是"任何改动必须经提案-裁决"。那条是为防 AI 乱写，
**但它顺带把人也挡在了外面**：改一句话在 md 里 5 秒 $0，在页面上要 32.5–63.7 秒 $0.26–0.74。
而讨论中最高频的动作恰恰是改措辞、挪位置、删一句 —— 工具必然被绕开。

| 发起者 | 路径 | 落盘 |
|---|---|---|
| **人** | 就地编辑：改标题／职责／正文／`parent`／删节点／改成熟度 | **直接生效，不走草稿，不花钱不等待** |
| **AI** | 只有 `propose` | 必须经预演 ＋ 人点采纳 |

判据是**谁发起的**，机械可判定（两条不同的 API）。**防 AI 乱写的强度一点没降。**

〔推论〕**闸门因此天然分裂成两套，不是一套跑两遍**（§9.1），人侧路径真正零阻塞。

## 4.2 模块会话流

上下文按模块切分（§5.1）。**`rev` 变则换会话**（§5.5）。

## 4.3 AI 巡检流

**事件驱动，不是轮询**：落盘 → 算影响面 → 排任务 → 遇冲突则等待。
比定时轮询省（没改动就不跑），且延迟更短。

**巡检是自动的 ⇒ 人不操作也在花钱。** 触发条件必须三个都满足：
模块静止 ∧ 自上次巡检后 `rev` 变过 ∧ 该模块未读建议未满额。
仪表加一行 `巡检：今日 $x ｜ n 次 ｜ [暂停]`。

○ 〔推论〕按单轮实测推算约 $2 起／天（8 次）。**这个数是推算，不是实测。**

# 五、依赖集：注入与失效的唯一来源

**这一节是本方案的技术核心。** 它把此前九条并列规则收成三个概念 ＋ 一条独立规则。

## 5.1 依赖集函数

> **依赖集 ＝ f(发起节点, 所在层级)**，返回一串 `(种类, 标识, 版本)`。

| 种类 | 注入什么 | 何时进入 |
|---|---|---|
| 自己 | 全部字段 | 总是 |
| 父链 | 祖先的 `职责` ＋ `正文` | 总是（祖先规定语境） |
| **全局约束区** | 全部条目 | 总是 |
| 依赖边 | 被 `依赖` 指向的节点的正文 | 有边就有 |
| 子 | 骨架 ＋ 状态聚合（**不含正文**） | 发起点在模块层以上 |
| **工作集 ∩ 本子树** | 近期**实际变更** | 工作集里有本子树的节点 |
| 一手片段 | 被 `依据` 引用的片段 | 有引用就有 |
| 裁决记录 | 本节点上发生过的裁决 | 总是 |
| `执行记录` | — | **v2** |

**依赖集不靠 AI 声明、不靠人标注**，由"人在哪个节点上发起"这一个事实机械算出。
纯函数，同输入同输出，可写否证测试。

**「工作集 ∩ 本子树」这一项是必须的**：人刚在 a1、a2 上干完活就跳到 a 层要"把两个一起调整"，
若父层会话不知道 a1／a2 刚改了什么，这次调整根本做不了；而它不能靠按需拉取——AI 不知道该拉哪两个。

**注入量随层级变化：**

| 人在哪一层 | 注入 | 不注入 |
|---|---|---|
| 叶子层 | 自己全部字段 ＋ **父链正文** ＋ 全局约束 ＋ 骨架 ＋ 依赖节点 | 兄弟的正文 |
| 模块层 | 自己 ＋ **子的骨架与聚合** ＋ 子上未解决冲突 ＋ 全局约束 ＋ 工作集内的近期变更 | **子的正文**（用按需拉取） |
| 根层 | 全局骨架 ＋ 全部跨模块冲突 ＋ 全局约束 | 任何正文 |

**按需拉取工具是必须的，不是优化项。**〔事实〕方案B 提交 `a6f3266`：
「`build_context` 总是喂节点索引 ＋ 新增 `read_nodes` 工具 —— 面级讨论此前在页面上做不到」。

## 5.2 一份依赖集，两个消费者

```
展开(依赖集)      → 文本，喂给 AI          ← 上下文注入
失效判定(依赖集)  → 有效 | 作废 | 过时      ← 冲突处理
```

**〔推论〕上下文注入与失效判定是同一个东西的两面。** 吃同一份依赖集，就不可能漂移 ——
注入了什么就监视什么，没注入的不监视。

依赖集是**那个"只在 `core.py` 算一次"的派生量**。
〔事实〕这条约束有实测支撑：方案A 实测到同一事实被算两遍给出两个数字；
方案B 提交 `300acdc 开合判定原有两个事实源`、`c765bd6 派生量被包装成内容` 是同类失效。

## 5.3 反向索引与传播深度

**反向索引 ＝ 依赖集的转置**，不落盘（落盘会引入第二事实源），实时转置得来。

节点 X 落盘（`rev+1`）⇒ 查反向索引：

| 距离 | 处置 |
|---|---|
| **1 跳**（直接依赖 X） | **作废**（在跑的任务、挂着的草稿、挂着的建议；聚合数字重算） |
| **2 跳**（依赖了"依赖 X 的东西"） | **过时提示**，不丢弃 |
| ≥3 跳 | **不传播** |

**阈值必须有（M16）**：不设限则改一个字全树作废。定在 2：1 跳保证正确性，
2 跳保住"还能用的草稿别白丢"，3 跳以上关联已弱到不值得打扰人。

**「作废」与「过时」的判据是读集**：任务**读过**的变了 ⇒ 结果不可信，作废；
**没读过**但相关的变了 ⇒ 结果可能仍有效，降级提示。混成一档会白丢有效草稿。

## 5.4 调度器的全部逻辑

```
收到委派(节点 n):
    若 n 上有未落地委派 → 合并两句，取消旧任务          # 去抖
    依赖集 = 依赖集(n, 层级(n))
    若 依赖集 ∩ 正在编辑集 ≠ ∅ → 排入等待队列            # 省钱：还没花
    否则 → 启动，记下依赖集与任务的「可否作废」标记

落盘(节点 X):
    rev += 1
    反向索引[X]          → 作废
    反向索引[反向索引[X]] → 标过时                        # v1 不做
    唤醒等待队列中不再相交的任务

人开始/停止编辑(X): 正在编辑集 ±= X ; 唤醒等待队列
```

**「等待」是「作废」的省钱前置版**：启动前发现会冲突就等，钱还没花；启动后才发现只能作废，
钱已经花了（〔事实〕$0.26–0.74/轮）。**同一条矛盾在两个时点上的处置，代价差一个数量级。**

**去抖合并是唯一保留的独立规则**（它关于人的输入节奏，与依赖无关）：同节点、未落地的连续
委派合并成一次，不排队。三条理由：省钱；语义正确（第二句通常是第一句的补充）；
**避免一个节点上同时挂两个草稿**——那时人要先合并两个草稿，代价爆炸。

○ 代价：若第二句是**推翻**第一句，合并后 AI 看到两句矛盾的话。处置：保留顺序并提示
"后者可能推翻前者"，让 AI 处理。比取消安全，取消会丢信息。

**未落地内容不参与别的任务**，除非人明确要等。问法必须是**就地一行**，不是弹窗
（弹窗会中断人正在打的字）。

## 5.5 上下文同步：这个问题被消灭，不需要方案

> **会话不持有内容的副本，只持有依赖集（引用 ＋ 版本）。每次发起时按依赖集重新展开当前内容。**

会话缓存的只有**对话历史**（不可变，一手层性质），永远不需要同步。内容永远现取，
所以不存在两个会话看到不同版本的问题。

**剩下的唯一真问题**：长驻会话（`ClaudeSDKClient`）把上一轮注入的内容留在**它自己**的历史里，
内容改了它记得的还是旧的。

△ 处置，机械可判定：**依赖集的版本变了 ⇒ 换新会话**，把该模块的**裁决记录 ＋ 当前内容**
重新注入，旧对话历史丢弃。

**跨天接续用裁决记录，不用对话摘要**：摘要是归纳会失真，裁决是事实不会。

〔推论〕**"换会话"与"跨天接续"是同一个机制**，不是两个。省一整块设计。

## 5.6 依赖项的两种形状（v2 预留）

| 形状 | 语义 | 失效条件 |
|---|---|---|
| **固定引用** `(标识, rev)` | 指定这一条 | 该条 `rev` 变了 |
| **最新查询** `(节点, 种类, latest)` | "该节点最新的 X" | **新增了一条同种的** |

v1 只用固定引用，但类型定义必须留出第二类。理由：一手层只追加，
"测试从通过变失败"表现为**新增一条失败记录**，固定引用永远指着那条旧的成功记录，看不见变化。

# 六、页面

## 6.1 单页三区

整个工具就是**一个 HTML 页面**（U2）。不再有"生成一堆视图文件、在多个页面间跳"。

```
┌─────────────┬──────────────────────────────────┐
│  地图        │  焦点                            │
│  工作集钉顶   │  当前节点全貌                     │
│  整棵树      │  标题/职责/正文/字段表            │
│  一行一节点   │  子节点摘要 / 依据栏(抽屉)         │
│  五种记号    │  [卡|树|…] 形态切换（候选集算出）  │
│             │  ← 草稿就地叠加（前后对照）        │
│             ├──────────────────────────────────┤
│             │  对话栏 ＋ 仪表(第N轮｜累计｜上一轮) │
└─────────────┴──────────────────────────────────┘
```

**左区回答"我在哪"，焦点区回答"当前是什么"。** 缺任一个，深入一层即失焦。

**「一个页面」这条约束的硬后果：草稿的前后对照不能另开位置，只能就地叠加在焦点内容上。**
它顺带砍掉了一整个模块——没有 `render.py`，页面直接从 server 取数据。

## 6.2 工作集与五种记号

**工作集 ＝ 最近触碰的 4 个节点**，钉在左区顶部，其余树折叠。
〔事实〕上限 4 有依据：工作记忆约 4 个组块（Cowan 2001）。这是"人的带宽有限、
一次只能在少量模块上思考"（U10）的直接落法。

**工作集同时是父层会话的上下文来源**（§5.1）。一个东西两个用途，且由同一个事实
（最近触碰）派生，不可能漂移。

```
场地      ✎ 我正在改
嘉宾      ⚑1 建议
预算      ⟳ AI 进行中（0:41 ｜ 预估 $0.4）
现场      △3 未确认
报名      ○ 待议
```

○ 工作集钉顶与显示树挤同一块屏幕，屏幕预算未算。

## 6.3 AI 产出的三种去向，视觉不可混淆

| 去向 | 形式 | 不处理的命运 |
|---|---|---|
| **建议** | 就地记号 | 冲突类**不过期**（过期就是掩盖真问题），优化类过期并计账 |
| **草稿** | 就地叠加，**可编辑** | 悬着，不落盘 |
| **待选区** | 并列，**可拆零件** | 悬着；未选者进档案 |

**若三者混淆，人会把"AI 建议了"当成"已经写进去了"——那是静默失效。**

**允许全局计数**（`待处理草稿 3`），**不允许全局内容列表**。计数不淹没人，列表会。

**结果回流绝不打断**：只加记号、计数 +1，**不弹窗、不跳转、不抢焦点**。
人正在别处思考，打断就是直接砸带宽。

**未选方案不删，进档案**：理由与"否决须填理由"同源——"当时为什么没选那个"有价值，
删掉之后同一个方案会在第五轮被重新提一遍。

## 6.4 并置的宽度代价

场景要求 `提炼 | 原话` 并置，也要求 `改前 | 改后` 就地对照；两者同时发生时需要三栏，
而焦点区在 1440 宽屏上只有约 900px，里面还要装标题／职责／正文／字段表／子节点摘要。
**装不下。这是"一个页面"这条约束的真实代价，不是实现细节。**

△ 选**抽屉**（依据栏默认收起），并配一条补偿：**提炼与原话可疑时主动弹开**
（长度差异过大，或 `依据` 指向的片段与提炼字数比失衡）。

**代价照实记：「失真当场可见」降级为「可疑时可见」，强度真的降了。**

# 七、委派：六类模式

| 类 | 人说什么 | AI 产出 | 去向 |
|---|---|---|---|
| **A 检查** | （巡检自动） | 问题，不产内容 | 建议 |
| **B 完善** | "我写了三句，你补全" | 内容 | 草稿 |
| **C 出方案** | "有哪几种选法" | 2–4 个候选，各带代价 | 待选区 |
| **D 探路** | "我还漏了什么" | 一批候选节点 | 待选区 |
| **E 整形** | "分域不对，重排" | 大批 `parent` 变更 | 草稿（**须分簇**） |
| **F 巡检** | （自动） | 同 A | 建议 |

## 7.1 人主刀：夺刀权

**AI 的任何产出都必须可就地编辑，不是只能采纳／否决。**
人在草稿上直接改字，改完那部分的 `来源` 从 `△AI` 变成 `◆人改过 n 处`。

**这是"主刀"区别于"审批者"的核心动作**：审批者只能是／否，主刀能夺过手术刀（U8）。

**原子性保在"落盘"这个动作上，不保在"AI 说了什么"上**：草稿在被采纳前是可编辑的草稿
（改草稿不落盘、不花钱、不等待），人改完 → 重新预演 → 采纳。

〔推论〕这条顺带取消了"按簇部分采纳"的需求：**人不需要"只采纳其中 3 条 op"，
他直接把不要的从草稿里删掉。**

**中断**：AI 输出到一半人点【停】，已输出部分留作草稿标"未完成"。
**中断不退款**，花费照实记进仪表。

## 7.2 自动化偏差：分档，且只有账没有拦截

| 模式 | 默认值指向 | 处置 |
|---|---|---|
| A／F 巡检 | **安全**（不理它，内容还是人自己的） | 无需额外机制 |
| B／C／D／E 委派 | **危险**（整段采纳最省力） | **只有 △账一条防线** |

〔事实〕方案B 的 4 条裁决**全部是采纳、0 否决**——那就是 C1（自动化偏差 × 自信地错）的样子。

**△ 不加拦截**（例如"AI 生成的正文必须人改过至少一处才能采纳"）：那会逼人做无意义的改动
来过闸，形式上通过、内容上失效。**账 ＋ 可见，是这一类问题唯一不自欺的处置。
代价照实记：它拦不住任何东西，只能让人看见。**

且 △账**只对已承诺区计**（§2.1）：念头区里 AI 帮人想出好点子、人原样收下，没有错。

# 八、导入与自动检索

**导入可在任何时间、任何位置发起**（U4）。位置 ＝ 当前聚焦的节点。

## 8.1 三段式，不许合并

两个极端都不通：导入即提炼 ⇒ 一份 30 页文档瞬间生成 80 个节点（C4 的教科书式触发）；
导入只入库不处理 ⇒ 材料等于没导入，负担回到人的记忆（C5）。

| 段 | 何时 | 谁做 | 产出 |
|---|---|---|---|
| **入库** | 导入瞬间，无条件 | 机器 | 原件不动，落进 `材料/` |
| **索引** | 导入瞬间，无条件 | 机器 | 按标题／空行切片，每片一个 id；产出**片段清单**（标题＋前若干字），**不是内容归纳** |
| **提炼** | **按需**，由人在具体节点上发起 | AI，经草稿-裁决 | 节点／字段，每条带 `依据` |

**索引是关键的中间态**：让材料**可寻址**，同时**不生成一个字的内容**。
切片判据是形式的（标题、空行），与领域无关，机器能做且可复现。

**整份材料永远不许塞进每轮上下文**——只有被 `依据` 引用的片段 ＋ 当前节点挂着的片段进上下文。
切片是上下文组装的前置条件，不是为了好看。

**导入切出 0 片 ⇒ 明确报错，不许静默入库。** 静默入库会让人以为材料在里面。

## 8.2 格式范围

**v1 只做粘贴文本 ＋ 拖入 `.md`／`.txt`。**

不是省事，是**切片判据的可靠性**：md/txt 按标题与空行切，切错了人一眼看得出。
**PDF 与图片要解析，而解析失败是静默失效**——切出一段乱码或漏掉两页，片段清单看起来完全正常，
然后 AI 基于残缺材料给出提炼并标上依据，整条保真链变成假的。

PDF 若要做，必须有**可见的解析失败信号**（每片显示原文页码 ＋ 一个"看原文这一页"的入口）。

## 8.3 自动检索

AI 用检索工具找到东西 ⇒ **存原始内容为材料** ⇒ 走同一个三段式。
**AI 的总结是提炼，必须标 `依据` 指向那份材料**（否则外部检索来的东西是二手的，
而一手层要求不可改）。

△ **建议提进 v1**：风险最低（只增材料，不动本体），复用现有机制最多，
且直接服务于"迸发创意"——念头刚出来时最缺的就是"这事别人怎么做的"。

## 8.4 材料的账与空位

页面就地显示每份材料的账：**n 片 ｜ 被引用 x 片 ｜ 进过上下文 y 片 ｜ 从未触及 z 片。**
对治一个很具体的错觉：**"我导入了 ⇒ 它读过了"**。事实上可能一片都没进过上下文。

○ **切片粒度**：片段要小到能精确引用，又要大到语义完整。按标题切，一节 3000 字就是一片，
喂上下文撑爆；切碎了，一个论点被切成 5 片，引哪片都不完整。
纯长文本（微信复制的一大段）没有标题也没有空行，切不出片；按空行切可能切出 1 个字的片。
**无解法。v1 的处置是把切片结果整个摆给人看**（片段清单就是给人核对的），
切错了人当场看得见——**这是把无解的问题转成可见的问题，不是解决它。**

○ **材料版本**：新报价来了，旧的不删（一手层只追加），节点的 `依据` 从旧片切到新片，
切换动作进裁决记录。代价：材料只增不减。

**"依据变了但内容没跟着变"的记号，用轮次比较即可，不需要指纹**：
一手层不可改，所以片段内容不会漂移；换依据这个动作本身进 `裁决.jsonl`，
比较 `依据的变更 rev > 内容的变更 rev` 就够。零新增字段。

# 九、闸门与账

## 9.1 闸门：按发起者分裂成两套，且按成熟度作用

**人的编辑要就地生效不等待 ⇒ 闸门不能阻塞人。** 但闸门要拦。

| 类 | 例 | 在哪拦 |
|---|---|---|
| **结构性** | `parent` 悬空、成环、id 冲突 | **UI 层预防**（拖拽不允许拖成环），不在落盘层拦。人做不出这些 |
| **内容性** | 未登记字段、提炼无依据、否决无理由 | **只在 AI 草稿预演时拦**。人手写不会触发 |
| **人确实会触发的** | 模块无职责、超屏占 | **提示档，就地记号，不阻塞** |

**v1 的闸门清单：**

| 闸门 | 档 | 作用区 |
|---|---|---|
| 悬空引用（`parent` / `依据` / `依赖`） | 拒绝 | 全区 |
| 无环 | 拒绝 | 全区 |
| **未登记字段** | 拒绝 | **仅已承诺区** |
| **提炼无依据** | 拒绝 | **仅已承诺区** |
| 否决无理由 | 拒绝 | 全区 |
| 模块无职责（有子节点却说不出职责） | 提示 | 仅已承诺区 |
| **△假设记号**（`来源=△AI` 且从未被人确认） | 提示 | 仅已承诺区 |

**「模块无职责」有两个理由，第二个更硬**：不只是"模块化要可判定"，而是
**`职责` 是全局骨架里代替正文的东西 —— 缺了它，这个模块对其他所有会话不可见**（§5.1）。

**巡检的任务类型必须显式化**（"检查/优化/完善"太笼统，实现不了也测不了）：

| 类 | 任务 | 机器可辅助 | v1 |
|---|---|---|---|
| 1 | **节点字段 vs 全局约束的冲突** | 是 | **做** |
| 2 | 这条内容该不该提升为全局约束 | 半（AI 提议，人确认） | 迭代 |
| 3 | 潜在跨模块依赖边 | 半 | 迭代 |
| 4 | 局部优化建议 | 否，纯 AI 判断 | **最后做** |

**前三类有判据、可写否证测试；第四类只能靠人觉得有没有用**，故排最后。

## 9.2 四本账（外部记账）

〔事实〕依据是 C6：越依赖 AI，理解测验低 17%，且客观慢 19% 而主观觉得快 20% ——
**人对自己验证力的下降没有知觉，只能靠外部账目。**

| 账 | 内容 |
|---|---|
| △账 | `n 个节点 ｜ 正文 x% 由 AI 生成且未改一字 ｜ 委派 m 次，其中 k 次整段原样采纳` |
| 巡检花费 | `今日 $x ｜ n 次 ｜ [暂停]` |
| 材料引用 | 见 §8.4 |
| 过期建议 | `AI 提了 30 条，你看了 4 条，26 条过期了` —— **这个账本身就是信号**：要么 AI 提的没价值，要么人的带宽已满，两种情况处置不同但都要先看见 |

## 9.3 否证测试是硬要求

**每条新闸门先注入一个它应当拒绝的情形、确认它真的拒，再声称它有效。**

○ **本方案最危险的静默失效，v1 只有一条弱防线**：
**AI 可以一个新字段都不加，把新概念当散文写进 `正文`。** 此时未登记字段闸门恒绿、
报告全通过，而结构化实际上已经停止——**形式上通过、内容上失效，且完全静默。**

△ 防线（便宜）：记录 `正文` 字数随 `rev` 的变化。**平均字数单调增长而开放字段数不增
⇒ 内容在往散文里逃。**〔待检验〕构造一轮"AI 只往正文里加 300 字、不加字段"的草稿，
断言这个指标动了。

# 十、v2 预留：五条现在做，三条不做

**"预留"的判据只有一条：会不会迁移数据。** 不会迁移的一律现在不做——
预留会变成过度设计，那是从概念出发（禁 6）。

**更强的标准：真预留会让 v1 期间产生的数据在 v2 直接可用**，而不只是"留了个位置"。

**检验方式：纸上把 v2 走一遍，看它碰到 v1 的哪些结构。** 已走过一遍，结论如下。

## ⚠ 必须现在做对的五条

**1　骨架含 `验证判据` / `执行动作`，各三档 `○无／愿望／可执行`**

「愿望」这一档是关键。〔事实〕原则已定：**约束必须编译成可执行的检查点，
编译不了的显式标为愿望**。v1 就允许人和 AI 写下"这条该怎么验证／该怎么做"，
**不要求它可执行**。v2 的工作是把愿望编译成可执行的东西，而愿望是 v1 期间攒下来的。

若 v1 不给这两个字段位置，这些话会散落在 `正文` 里，v2 要人工提取。

**2　一手层的类型是开放枚举**（§3.3），否则 v2 加 `执行记录` 要迁移。

**3　依赖项有两种形状**（§5.6），否则 v2 要迁移全部依赖集。

**4　调度器的任务带「可否作废」标记**，v1 全填"可"。
② 秒级无副作用可作废；④ 长时有副作用不可作废（要回滚）。加一个布尔，v2 只增分支不重写。

**5　原则：本体存陈述，一手层存痕迹**（§3.6）。零成本，但没有它 v2 会发现本体已被污染。

## ✓ 明确不预留的三条

**工作区／沙箱**——完全不碰本体，是纯新增。〔事实〕方案B §十 把"工作区／爆炸半径"
列为不做，那个判断仍然对。

**多 agent 编排／插件系统／agent 市场**——预留它们要引入抽象层，
而**抽象层在没有第二个实例之前是凭想象加的**（M1、禁 6）。等真有第二种执行器再抽。

**权限审批工作流／分布式执行**——同上。

## 关于"现在应该有成熟的框架"（U14）

△ **这句话对了一半，而没对的那一半正是难的部分。**

〔事实〕**执行的机械底座已经在手上**：方案B 用的 `claude-agent-sdk` 0.2.129 本身就有
工具调用、`Bash`、文件编辑，以及 `can_use_tool` / `PreToolUse` 权限钩子 ——
方案B 实测过用 `disallowed_tools=[Edit, Write, NotebookEdit, Bash]` 把写权收干净，
反过来放开是同一个开关。隔离用 git worktree 就够。验证就是跑测试，无特殊框架需求。

**没有现成东西的是这一半**：跑完了，输出是一堆文本和退出码；
**这堆东西凭什么让一个想法的状态从"已承诺"变成"已验证"？**
判据谁定、失败算谁的、部分通过怎么算、结论进本体时该写成什么。

〔推论〕**v2 的难点不在"能不能执行"，在"执行结果与想法之间的对应关系"。**
上面五条预留全部是为这段语义留位置，不是为执行能力留位置。

# 十一、场景

保留两个。第一个是从零到第一次承诺，第二个是本方案架构的检验点。

## 11.1 冷启动到第一个承诺

主题：**筹备一场 200 人的线下活动**（非软件主题，用来检验"通用"不是声明的）。

1. 打开页面。左区空，焦点区一句话：「说一句就行，不用说清楚。」
   **第一屏不能是空输入框**（等于要求人先构造），**也不能是长问卷**。
2. 人打一句 `我要办一场 200 人的线下活动，10 月，预算 8 万左右`。原话一字不改入库。
3. AI 出**候选骨架树**：5 个顶层节点，各只有 `标题` ＋ `职责`，`来源=△AI`，`成熟度=念头`。
4. 焦点区下方「**AI 猜了这些**」三条，每条带 `[确认] [改] [不重要]`。
5. 人**剪枝**：删掉「宣传」，把「当天执行」改名「现场」，加一个「报名」。
   **人在识别，不在构造。** 剪枝由一键裁决承担，v1 不做拖拽。
6. 人下潜到「场地」，说了一长段（含一个条件句）。AI 提炼成 `立场`／`论据` ⇒ 论证图形态。
   **人一眼看到 AI 漏了条件句** —— 图形没有逻辑联结词，条件／否定／全称／时态装不进论证图。
   故论证图旁必须常备**受控文本**形态。
7. 人把「场地」的成熟度改成 `已承诺`。**晋升门在此触发**：补登记字段、补 `依据`、消解矛盾。
   这是全流程里唯一集中付摩擦的地方。

○ 代价：AI 一上来给 5 个，其中可能有 2 个完全不对。"剪枝"是否真比"从零自己建"便宜，
**无数据**。走通后实测第一屏之后 5 分钟内树的净增删比。

## 11.2 多模块游走：一条连续时间轴

树（三层五模块十二叶子），映射到 U10 的记号：
**a ＝ 报名**（a1 ＝ 表单字段，a2 ＝ 人数上限与候补），**b2 ＝ 场地/锁定时间线**。

| 时刻 | 人 | AI 任务队列 | 机制 |
|---|---|---|---|
| 0:00 | 在 **a1** 自己改字段列表 | 空 | 流①，即时落盘，$0 |
| 0:40 | 在 **a1** 委派生成校验规则 | **T1 启动**，依赖集含 a1 | — |
| 0:55 | **不等，跳到 b2** | T1 跑 | 姿态：走开 |
| 1:10 | 在 **b2** 把锁定日 6/1 改成 5/20 | T1 跑｜**T2 排入不启动** | 落盘触发影响面；T2 依赖集含 b2 而人还在 b2 ⇒ **等待** |
| 1:25 | 人在 b2，不知道 | **T1 回来** | a1 出 `⚑`。**不弹窗不跳转不抢焦点** |
| 2:05 | 离开 b2，跳到 **a2** | **T2 启动** | 等待解除 |
| 2:10 | 在 **a2** 委派候补规则 | **T3 遇岔路** | 依赖集含 a1，而 a1 挂着**未落地草稿** |
| 2:12 | 就地一行（**非弹窗**）：`a1 有未处理草稿 [等它落地] [按已落盘内容做]` → 选后者 | **T3 启动** | 未落地内容不参与别的任务 |
| 2:30 | 在 **a2** 又想到一句 | **取消 T3，合并重跑 T3′** | **去抖合并**，前次花费已计入 |
| 2:50 | — | **T2 回来** | 冲突：嘉宾截止 6/5 > 新锁定日 5/20，挂两处，**不过期** |
| 3:20 | 在 **a2** 等到 T3′，改两处后采纳 | 落地 | 落盘 → a1 的 T1 草稿标**「可能已过时」**（非作废） |
| 3:40 | 跳到 **a 层**：`a1 和 a2 有重复，统一掉` | **T4 启动** | 注入含**工作集内 a1／a2 的近期变更**（§5.1） |
| 4:20 | T4 出跨三节点草稿；人删掉一条后采纳 | — | 原子采纳，但草稿可编辑 |
| 4:30 | 回 a1 看那个「可能已过时」的草稿，还能用 → 采纳 | — | **过时 ≠ 作废**，否则白丢 $0.3 与一个正确产出 |

**这条时间轴之外还有一个跨天的检验点（本方案的核心检验）：**

周一在「场地」定下"不能卖票"并**提升为全局约束**；周三在「预算/收入」说
`收入按门票 100 元 × 200 人算`。

| | 会发生什么 |
|---|---|
| 若未提升为全局约束 | "不能卖票"住在「场地」的正文里，不在骨架里 ⇒「预算」会话不知道 ⇒ 顺着算出 2 万收入 ⇒ **内容自相矛盾，两个会话各自都对，全程无信号** |
| 因为提升了 | 全局约束在依赖集里 ⇒ AI 当场顶回："与全局约束『不能卖票』冲突" |

**这就是"上下文跨时间跨空间传递"的判据**：周一 18:00 在「场地」建立的一条认识，
周三 14:00 在「预算」会话里起了作用，中间隔 2 天、4 个模块、2 个层级。

〔推论〕**这也证伪了一个更早的设计版本**：全局骨架（`id`＋`标题`＋`职责`）
**不足以**承载跨模块约束，因为约束住在正文里。必须有独立的全局约束区 ＋ 提升机制。

# 十二、v1 范围

切法判据（U5：先按简单的做）：

| 切法 | 后加的代价 |
|---|---|
| **砍广度**（安全） | **加法**。形态由字段算出，多一种形态是多一个分支；数据不动 |
| **砍机制**（危险） | **迁移**。数据模型层的东西后加要把已存内容重做一遍，而那时已有真数据 |

**且有一条更硬的理由：**〔事实〕方案B 已经证明过"页面上能跟 AI 对话并改内容"。
**若 v1 把机制全砍了，它走通也只是把 B 证明过的事再证一遍，一点新东西都没检验到。**

## 12.1 必须有（数据模型层）

1. 骨架九字段（含 `成熟度` 完整取值域、`验证判据`／`执行动作` 及其"愿望"档）＋ `last_rev`
2. `rev` 全局单调计数
3. 开放字段 ＋ `字段词典.yaml` ＋ 未登记字段闸门（仅已承诺区）
4. 一手层三类**开放枚举**（`执行记录` 留位），不可改只追加
5. `依据` 去向＝一手层任一条目
6. **全局约束区（`G-` 子树）＋ 提升机制**
7. `依赖集()` 全项 ＋ `展开()` ＋ `失效判定()` ＋ `反向索引()`；依赖项**两种形状**（只用第一种）
8. 调度器：正在编辑集、等待队列、去抖合并、**任务带「可否作废」**
9. 会话生命周期：依赖集版本变则换会话，裁决记录接续
10. **写盘权按发起者分**（人直接落盘，AI 经草稿-裁决）
11. 导入三段式分离
12. 草稿**就地叠加**在焦点区、**可编辑**、改后重新预演
13. 内容 hash 前后端比对（防局部更新漏项导致人在过时视图上裁决）
14. 仪表（第N轮｜累计｜**上一轮**）＋ 两段式「新会话」手闸 ＋ 巡检暂停开关
15. △账一行

## 12.2 只做最小

|---|---|---|
| 传播 | **只做 1 跳作废** | 2 跳过时提示 |
| 调度 | 等待 ＋ 去抖 ＋ **并发上限 2** | 优先级、抢占 |
| 巡检任务 | **只做第 1 类**（字段 vs 全局约束冲突） | 第 2、3 类，第 4 类最后 |

| 反馈 | 就地批注、一键裁决、空位填答 | 划词追问（v1 退化为锚到字段）、对照挑选、拖拽 |

| 依赖边 | 人手建 | 巡检提议建边 |
| 导入 | 粘贴文本 ＋ `.md`／`.txt` ＋ **自动检索** | PDF（含页码回溯与可见解析失败信号） |

## 12.3 明确不做（YAGNI）

自动验证／自动执行的**实现**（只留 §十 那五条预留）｜工作区／爆炸半径／回滚 ｜
E 类（AI 重排结构）｜多卡并列 ｜依赖图的图形化 ｜多 LLM 适配器 ｜多人协作 ｜
抢占式调度 ｜巡检用便宜模型

**E 类不做的代价照实记**：大规模重构 v1 只能人自己拖。
〔事实〕本项目 08-07 三次提交都是重构，所以这一条 v1 是硬扛。

## 12.4 模块划分

| 模块 | 职责 |
|---|---|
| `core.py` | **派生量唯一实现处**：`依赖集()` `展开()` `失效判定()` `反向索引()`，形态候选集、聚合、字段登记校验、△集合 |
| `schedule.py` | 调度器：正在编辑集、等待队列、去抖、并发上限、可否作废 |
| `session.py` | 会话生命周期：版本变则换会话，裁决记录注入 |
| `proposal.py` | 草稿 ＋ 预演 ＋ 乐观锁 ＋ 原子落盘 |
| `material.py` | 导入前两段（入库 ＋ 切片索引）。独立成模块：切片判据会反复改，且它一个字都不碰内容体 |
| `check.py` | 闸门 ＋ 否证测试 |
| `llm.py` | LLM 接缝 ＋ `MockBackend` |
| `server.py` | ASGI ＋ SSE，**唯一有写盘权的东西** |
| `page.html` | 单页三区 |

**没有 `render.py`**（§6.1）。

**`MockBackend` 不是"以后接别的 LLM"的预留，它有当下就成立的用途**：
〔事实〕真跑一轮 32.5–63.7 秒／$0.26–0.74。没有 Mock，端到端测试跑一次这个代价，
**实际等于没有端到端测试**。

## 12.5 技术底座（全部为方案B 的实测，非推演）

〔事实〕`claude-agent-sdk` 0.2.129，走现有 OAuth 订阅，**不需要 API key** ｜

# 十四、走通判据（v1 验收，不接受近似达成）

1. 空页面 → 一句话 → 候选骨架树 → 人剪枝
2. 拖入 `.md` → 片段清单 → 挑 2 片挂上 → **`内容.yaml` 的 hash 一个字节没变**（三段式真的分开）
3. 人自己改一句话 → **即时落盘，零等待零花费**，且 `裁决.jsonl` 有记录
4. 人在 a1 委派后**走开去改 b2**，结果回来时**不弹窗不跳转**，只加记号
5. 人在 b2 编辑期间，依赖 b2 的任务**处于等待、没有启动**（省钱路径真的走通）
6. 人在同节点连说两句 → **合并成一次**重跑，不是排两个任务
7. 改全局约束 → 在跑的相关草稿被标**作废**
8. **跨天检验点**：在「预算」说"按门票算收入" → AI 顶回"与全局约束冲突"
9. 跨天重开「场地」会话 → 注入的是**裁决记录**不是对话摘要
10. 已承诺区里，AI 草稿的未登记字段被拦；无 `依据` 的提炼被拦并**回 AI 自修，人看不到**
11. 念头区里，同样的草稿**不被拦**（§2.1 的分区真的生效）
12. 一个节点的成熟度从 `想法` 改为 `已承诺` → **晋升门要求补齐登记与依据**
13. AI 的草稿**可就地改字**再采纳，改过的部分 `来源` 变为 `◆人改过`
14. **全程不回终端**
15. **对照组**：同一任务做两遍（一遍用工具，一遍直接聊＋写 md），记人的用时、
    产出的「已承诺」条数、未审内容占比

第 14 条是核心：前 13 条做到而它做不到，等于没走通。
第 15 条是唯一能回答"好不好用"的那条。

**测试层次**：闸门否证（每条注入一个应被拒的情形）｜三段式否证（导入后断言内容 hash 未变）｜
乐观锁否证 ｜依赖集否证（构造边界，断言算出的依赖项集合）｜端到端（`MockBackend`，秒级免费）｜
写权限回归（真跑 AI 并要求它改文件，断言事件流无 Edit／Write，`--live` 才跑）

# 十五、错误处理

| 失效 | 处置 | 依据 |
|---|---|---|
| 预演出拒绝档冲突 | 草稿**照样完整显示**，采纳按钮禁用并写明原因 | **显示 ≠ 落盘。** 拦落盘是闸门职责，拦显示是抢裁决权 |
| 文件被外部改过 | 落盘前比基线指纹，不一致 → 409，要求重新预演 | 自举期两人会同时动同一批文件 |
| AI 进程死／连接断 | 持久化 `session_id`，resume 重连 | 〔事实〕方案B 实测可 resume |
| 落盘中途崩 | **先记账后落盘**，崩后可重放 | 跨文件无法真原子 |
| 草稿结构非法（字段路径不存在、id 指不到） | 回 AI 自修，**不升级给人** | 机械接地归 AI，语义冲突归人 |
| 导入切出 0 片 | 明确报错，**不许静默入库** | 静默入库 ⇒ 人以为材料在里面 |
| 局部更新与文件不一致 | 每次更新后拉内容 hash 比对，不一致强制整页刷新并显目提示 | 〔事实〕方案B 踩过两次同类（`300acdc`／`c765bd6`） |
| 人长期占着一个节点 | 等待队列须有超时（强制启动或放弃） | ○ 阈值未定 |
