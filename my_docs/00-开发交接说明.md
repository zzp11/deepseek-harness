## 4. 技术事实速查（已验证，含关键路径）

### 插件包协议
- 函数插件三件套：`export const name` / `export const inject = [...]` / `export function apply(ctx, config)`。注册即 effect（dispose 自动注销，天然热重载）。
- Config 用 schemastery：`export interface Config {...}; export const Config: z<Config> = z.object({...})`（参考 `packages/web/web-search-deepseek/src/index.ts:46-74`）。

### 自定义工具
- `ctx.tools.register(defineTool({name, description, parameters, output:{schema, render, presentationMeta?}, execute(args, exec), presentCall?, presentResult?, timeoutMs?, isConcurrencySafe?}))`
- 契约参考 `docs/cookbook/adding-a-tool.md`（canonical JSON 返回值、exec.signal 取消、presentation 纯度）。
- 工具 schema 自动进系统提示词；`ctx.systemPrompt.section({name, order, text})` 加自定义章节。

### 自定义会话事件（一手层/本体的持久化载体）
- `declare module '@deepseek-ai/dsh-session/types' { interface SessionEventMap { 'workbench/snapshot': {...} } }`（范例 `packages/web/web-search-deepseek/src/provider.ts:80-85`）。
- 写入：`session.append(type, data)`（`packages/core/session/src/index.ts:604-655`，data 须 JSON 可序列化）。
- 订阅：`ctx.on('session/event', (session, event) => ...)`。
- 持久化自动（session-persistence JSONL/SQLite）；事件经 `events.mux` 实时推浏览器（`packages/host/apiproxy/src/api-proxy.ts:3475-3493`）。

### 人审（草稿-裁决）
- `ctx.approval.request({agent, toolName, reason, signal})` → `'allowed-once'|'rejected'|'cancelled'|'unavailable'`（`packages/interaction/user-approval/src/index.ts:153-276`）。
- `ctx.userQuestions.ask({questions, agent})`（`packages/interaction/user-questions/`）。
- 本阶段 0 的裁决走**自定义 RPC**（见下），approval 用于工具管线内需要人确认处。

### 自定义 RPC（人的编辑 API）
- apiproxy：`packages/host/apiproxy/src/api/rpc-map.ts` 注册方法（`POST /api/<method>`）；实现放 `src/api-proxy.ts`。客户端经 `ctx.connection.api` 调用。**这是仓库内修改，正是模式 A 的原因。**

### 客户端插件（工作台 tab）
- 包声明 `dsh.client: { platform:'web', ... }` + `exports["./client"]`；打包用 `clientBundle()`（`packages/client/tsdown.client.ts`）。
- 注册工作台 tab：`conversation.view` list 槽（参考 `packages/client/ui-trajectory`）；`conversationEvents.register(Definition)` 折叠 `workbench/*` 事件成树 State（参考 `docs/cookbook/adding-a-conversation-node.md` 的 review-job 范例）。
- 装载：往 `packages/bundle/web-app/cordis.patch.yml` 的 browser roster 加行（参考现有 `ui-tool` 等行）。
- 客户端插件改动**不重建 web 壳**：`pnpm run dev:web` watch 重写 client bundle + 热载（只对 client-plugin 生效）。

### 服务清单（插件可用）
`ctx.llm.stream`（直接发模型请求）｜`ctx.fs`（受沙箱约束）｜`ctx.sessions` / `ctx.agents`（多会话/agent.followup）｜`ctx.jobs` / `ctx.subagents`（后台任务）｜`ctx.settings` / `ctx.credentials`｜`ctx.storage`（JSON/SQLite KV）｜`ctx.workspaceRegistry`。

## 6. 纪律与风险

- **不要热载坏客户端插件进正在运行的 3080 实例**：本机有一个正在运行的 dsh web（工作区 dsh-workplaces/test），`dev:web` HMR 会把新 client bundle 热载进去。开发用独立 worktree + 独立端口（`--port 3081`），验证通过后再考虑尝鲜。
- 服务端坏代码对运行实例无影响（进程加载的是已构建产物）；但改坏仓库内 bundle 配置并重启可能让实例起不来——用 worktree 隔离。
- DSH 预发布，API 会破坏性变更；遇到与方案冲突的 DSH 事实，先记录后调整方案，不要硬绕。
- 仓库门禁（若提交 PR）：per-file 100% coverage（test:coverage）、doc-sync、snapshot 政策——先本地开发，提交时再对齐。
- `rev` 批处理语义、原话镜像、accept-proposal 重跑闸门（重新预演）是三条硬修正，实现时勿丢（方案 §五/§九）。
