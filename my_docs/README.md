## 关于 90-方法论前提

它规定了本项目**怎么思考、怎么下结论、怎么标记未定项**，不是编码规范。
**它不会被自动加载**（只有仓库根的 `CLAUDE.md`／`AGENTS.md` 会）。若希望它在 DSH 侧生效，
需显式引用，或把关键几条摘进你自己的工作约定。与开发直接相关的是这几条：

- **标记规范**：`〔事实〕`（有一手证据，附来源）／`〔推论〕`／`〔假设〕`／`〔待检验〕`；
  `◆` 用户提出 ／ `△` 我提出 ／ `○` 悬空未定。**宁可留空位，不许沉默填补。**
- **派生量只算一次**：任何派生量只在 `core` 计算一次，检查器／渲染器／页面 JS 一律只消费。
  依据是实测过的失效：同一事实被算两遍、给出两个数字。
- **新增闸门先做否证测试**：注入一个该闸门应当拒绝的情形，确认它真的拒，再声称它有效。
- **不许凭印象声称"一致""已覆盖"**：跑检查器并报告真实输出。

## 阶段 0 是什么、不是什么

**是**：`空页一句话 → AI 出候选骨架 → 人剪枝 → 晋升门 → 已承诺` 的最小闭环，
外加两条硬约束成立 —— 人的编辑即时落盘零等待零花费；AI 只能 `propose`，产出必经人裁决。

**不是**：完整的方案C。`01` §十七 诚实列了 7 条偏差，其中最重的是
**巡检流缺席** —— 而设计说明 §2.4 论证过它是**架构必需**（落盘即时与一致性检查的共存机制），
不是可选功能。阶段 0 的一致性只在写路径上检查。

**验收只覆盖设计说明 §14 的判据 1 和 3**（共 15 条）。别把"阶段 0 走通"读成"方案C 成立"——
〔事实〕方案B 就是走通之后没被用（12 行对话、4 小时、4 条裁决全是采纳，
此后所有实质工作回到终端 ＋ md 文件），而当时的回填一条都没提"它有没有被用"。
