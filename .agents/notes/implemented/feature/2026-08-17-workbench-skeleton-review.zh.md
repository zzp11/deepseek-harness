# Agent Note：冷启动的骨架是一棵树，而且由人来裁决

Status: implemented

[English](2026-08-17-workbench-skeleton-review.md) | 中文

## Problem

拿真模型在真装配的页面上走了一遍，暴露出两个缺陷，合起来让模型**最有价值的那一份产出**完全用不上。

对一个空工作台说：`想在十月办一场 200 人的线下技术沙龙，预算 8 万左右`。模型先调 `workbench_read_nodes`，再调 `workbench_propose` 提了一棵九张卡的骨架、给根节点配了流程图、还给出一份预算科目表。然后「工作台」tab 上是：空目录、`说一句就行` 的空态、以及一行字 `草稿待裁决 / 冷启动骨架：…`。整个视图里所有可点的东西只有 `＋ 加一张卡`，加上提问面板自己的按钮。

**那份草稿够不着。** 采纳与不要只渲染在**被选中的卡片内部**，并且只过滤 `targetNode` 等于那张卡的草稿。冷启动的草稿谁也不指，树上又没有卡可选，于是它匹配不到任何地方，既不能采纳也不能拒绝。后面全部堵死，因为根本没有任何东西能落盘。

**冷启动的骨架无法描述一棵树。** `ProposedNode.parent` 是一个**已存在**的 `NodeId`，而冷启动时什么都不存在。模型在散文里写了「总纲牵头，下面挂八条线」，而 `parent: proposed.parent ?? proposal.targetNode` 把每一项都解析成了根——九个平级的根。结构模型早就想清楚了，采纳路径把它扔掉了。

第一个缺陷不是宿主的限制：`accept-proposal` 早就带着 `keptNodes?: {index, title?}[]`，文档写着「留在外面的下标会被剪掉，而剪枝发生在提交之前，所以被剪的节点从来没进过树」——正是场景 3.2／3.3 要的东西。**缺的只有浏览器这一侧的界面。**

## Decision

### `parentIndex` 按位置指出同一份草稿里的父节点

`ProposedNode` 新增 `parentIndex?: number`，必须指向同一个 `newNodes` 列表里**更靠前**的条目。严格向后指按构造排除了成环，而模型按从上到下写这棵树自然就满足。两者都给时它优先于 `parent`。

`planProposal` 会拒绝违反这条规则的草稿：这个字段只有模型会写，而一份形状根本搭不起来的草稿，值得在模型还能改的时候就拒掉。闸门跑在一张**包含草稿自己占位节点**的图上，于是 index 形式的父节点不会被当成悬空引用，而完全落在一份草稿内部的环也能被环检测看见。

采纳时**先给整个保留集铸 id，再解析父节点**，所以一张卡可以挂在同一次提交里新建的兄弟节点下。剪掉一张**仍有子节点被保留**的卡会被**拒绝**，不会悄悄改挂到根上：「门票」挂在「预算」下是一条预算科目，挂到根上就是一件自成一体的事，而这条拒绝把决定权交回给人，让他明确地去剪整棵子树。

### 骨架裁决界面自成一块，位置在卡片上方

`SkeletonReview` 把草稿渲染成一份缩进的候选卡列表，每张卡带可编辑的标题和一个「剪掉」，再加上采纳与不要。改名和剪枝都发生在**采纳之前**，因为宿主的契约是「被剪的卡从来没进过树」——事后再删是一个弱得多的说法：那个节点确实存在过、被依赖过、然后被删掉了。

它渲染在被选中卡片的**上方**，而不是取代它。以「没有选中卡片」为开关，会把原来那个 bug 往后挪一步复现：模型完全可能对一棵已经有卡的树再提一批顶层结构，而人永远看不到。

界面里剪一张卡也会剪掉它的子树，于是那个会被宿主拒绝的状态**根本不会被提供**。恢复只恢复被点的那一张——父节点回来，无从知道整棵子树是不是也该跟着回来。

## Alternatives considered

**接受扁平列表，让人事后自己改挂。** 否掉：结构模型本来就知道，扔掉它正是这个工具要消掉的那种损失；而且要人做 N 次拖拽，去恢复一份早就算出来的信息。

**让 `parentIndex` 指向列表里任何位置。** 否掉：向前指和自指正是环的入口，那样检查就得真走一遍图。只许向后指是一次比较，而且本来就是自上而下书写的自然产物。

**父节点被剪时把孤儿改挂到根。** 否掉：它在不声明的情况下改变了留下来那张卡的含义。拒绝更响亮，也把决定留给人。

**把裁决界面放进目录栏。** 否掉：左栏是「树里**有**什么」的目录。草稿不在树里，把候选放进去，会让唯一回答「现在有什么」的那一栏不再回答它。

## Testing

宿主：`edit.spec.ts` 覆盖「按草稿描述的形状挂好」和「保留的卡的父节点被剪时拒绝」；`propose.spec.ts` 覆盖「拒绝向前指或越界的 `parentIndex`」与「保留合法的那个」。

客户端：`tab.client.spec.tsx` 覆盖草稿出现在原来空态的位置、选中卡片时仍然在、原样采纳、只带上真正改过的标题、剪掉一棵子树、恢复其中一张、剪光之后拒绝采纳、不要时先问理由，以及第二份草稿不继承上一份的改动。

真装配：`workbench-salon.e2e.ts` 在宿主侧追加一份带形状的草稿，然后在真浏览器里驱动这个界面——缩进 `['0px','18px','36px']` 是从实时几何读出来的、子树的剪与恢复、采纳后保留的那一对按人定的标题落盘且被剪的那张不在树上、以及不给理由时拒绝完成「不要」。

裁决容器带 `data-skeleton-review`，因为 CSS Module 的 hash 是**前缀**：`[class*="_skeleton"]` 会同时命中容器和七个后代，没法用来数「有几份裁决」。

## Consequences

冷启动这条路端到端通了：在真页面上，七张卡在**同一个 `rev`** 里落盘，模型描述的层级保住了，人改的名字保住了，被剪的那张在树上找不到。

`parentIndex` 是**模型可见**的 schema 增补，所以工具编目和两个包的 README 与它同步。

客户端插件是从构建好的 `lib/` 提供的，所以对这个界面的修改在跑过 `pnpm --filter @deepseek-ai/dsh-client-workbench run bundle` 之前，对浏览器和 `apps/web/tests` 这条道**都是不可见的**。搞清楚这件事之前，已经在旧包上白跑了两轮。
